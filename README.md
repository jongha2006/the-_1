## 실행

프로젝트 폴더에서 Node.js 24 이상으로 실행하세요.

```powershell
node server.mjs --demo
```

브라우저에서 http://localhost:3000 으로 접속합니다. 데모는 서버 시작 즉시 25분 이벤트가 열립니다. 두 번째 문제는 7분, 코드 문제는 15분 뒤 공개됩니다. 데모 서버를 재시작하면 새 이벤트가 만들어집니다.

프로젝트 폴더에서 데이터 파일 쓰기가 제한된 환경에서는, 쓰기 가능한 기존 폴더 안의 파일을 지정할 수 있습니다. 현재 개발 미리보기는 아래와 같이 임시 폴더의 SQLite 파일을 사용합니다. 이 파일은 운영 데이터 저장 위치로 사용하지 마세요.

```powershell
$env:SECURITY_GAME_DB = Join-Path $env:TEMP 'security-shift-preview.sqlite'
node server.mjs --demo
```

기본 프로젝트 내 저장 방식으로 돌아가려면 새 터미널을 열거나 `Remove-Item Env:SECURITY_GAME_DB`를 실행하세요.

정규 일정으로 실행하려면:

```powershell
node server.mjs
```

서버를 켜 두면 한국 시간 매일 21시에 시작합니다. 같은 날 정규 모드로 재시작하면 기존 이벤트 기록을 유지합니다. 웹사이트는 상시 열리고 제출만 이벤트 중 가능합니다. 종료 후 현재 이벤트의 공개 문제를 열람할 수 있습니다. 과거 이벤트 선택 화면과 연습 재채점은 아직 없습니다.

## 닉네임·비밀번호 계정

- 화면 오른쪽의 로그인 / 회원가입에서 계정을 만듭니다. 닉네임 2~16자, 비밀번호 8~128자입니다. 닉네임은 유니코드 정규화 및 영문 대소문자 구분 없이 중복을 검사합니다.
- 비밀번호는 계정별 무작위 salt와 scrypt 해시로 저장합니다. 비밀번호 원문은 DB에 저장하지 않습니다.
- 로그인할 때마다 새 세션을 발급하며, DB에는 세션 토큰의 SHA-256 해시만 저장합니다. 세션은 7일 뒤 만료되고 로그아웃 즉시 폐기합니다.
- 반복 인증 요청은 10분 동안 IP당 60회, 닉네임당 12회로 제한합니다. 현재 제한은 서버 프로세스 메모리에서 관리합니다.
- 기존 v0.1의 비밀번호 없는 임시 참가자는 계정으로 자동 전환하지 않습니다. 새 계정을 만들어야 합니다. 기존 기록은 DB에 보존되지만 새 계정으로 이전되지 않습니다.
- 비밀번호 찾기/변경, 이메일 인증, 다중 계정 방지는 아직 없습니다.

## 매일 달라지는 당직 조

- 로그인 또는 로그인 상태로 당일 페이지 접속 시 당일 출석을 기록하고 임시 조에 자동 배정합니다. 접속 인원은 동시 온라인 인원이 아닌 당일 출석 계정 수입니다.
- 정규 모드는 한국 시간 20:55에 출석 인원을 무작위로 섞어 조당 약 4명으로 확정합니다. 조 수는 `ceil(출석 인원 / 4)`이고 조별 인원 차이는 최대 1명입니다. 예: 11명 → 3개 조(4·4·3명).
- 마감 전 임시 조는 확정 시 바뀔 수 있습니다. 화면에 임시/확정 여부와 마감 시간을 표시합니다.
- 확정 후 로그인하는 참가자는 가장 인원이 적은 조에 무작위 동률 선택으로 합류합니다. 기존 조원은 이동하지 않습니다. 늦은 참가가 많으면 조당 4명을 넘을 수 있습니다.
- 재로그인과 서버 재시작으로 조를 다시 뽑을 수 없습니다. 다음 날짜 이벤트에서는 새 출석과 조 편성이 이루어집니다. 당직 종료 뒤에는 새 출석을 받지 않습니다.
- 데모에서는 시작 1분 뒤 조를 확정해 빠르게 확인할 수 있습니다. 새 데모 이벤트는 새 조를 편성합니다.
- 조별 순위는 아래의 표준편차 가중 점수 기준입니다. 개인 순위와 공동 복구도도 유지됩니다.

### 표준편차를 반영한 조 점수

조원 개인 점수를 x, 단순 평균을 μ, 중앙값을 m, 모집단 표준편차를 σ라고 하면:

```text
α = 0.65 × σ / 개인 최대 점수(현재 300)
조 점수 = (1 − α) × μ + α × m
```

편차가 없는 조는 단순 평균과 같습니다. 편차가 커질수록 중앙값 비중을 높여 높은 극단값과 낮은 극단값의 영향을 모두 줄입니다. 현재 점수 범위에서 중앙값의 최대 비중은 32.5%입니다. 표준편차만으로 조 전체를 감점하지 않습니다. 무제출·미해결 조원은 0점으로 포함하며, 명단이 같은 상태에서 개인 점수가 올라가면 조 점수가 내려가지 않도록 계수를 제한했습니다.

| 개인 점수 | 평균 | 가중 조 점수 |
|---|---:|---:|
| 90, 90, 90, 90 | 90.0 | 90.0 |
| 90, 90, 90, 300 | 142.5 | 132.2 |
| 0, 90, 90, 90 | 67.5 | 69.4 |
| 0, 0, 0, 300 | 75.0 | 53.9 |

이 규칙은 통계적인 이상치 판정이나 부정행위 탐지가 아닌 게임 점수 설계입니다. 3~4명 규모에서는 한 사람을 이상치라고 단정하지 않으며, 개인 획득 점수는 바꾸지 않습니다. 같은 점수 분포를 가진 조는 인원 수가 달라도 같은 조 점수가 나옵니다. 인원 변경 자체로 점수가 변할 수 있으며, 지각 참가자도 처음에는 0점으로 포함됩니다. 반올림 전 점수로 정렬하고 정확히 같은 조 점수는 공동 순위로 표시합니다.

## 코드 채점 준비

Docker 엔진을 설치하고 실행한 뒤 공식 Node 이미지를 미리 준비하세요.

```powershell
docker pull node:24-alpine
```

게임 서버를 시작하면 이미지 준비 상태를 확인합니다. 실행 중 이미지를 준비한 경우 페이지 새로고침만으로 표시가 바뀌지 않을 수 있으므로 서버를 재시작하세요. Docker가 없어도 개념 문제, 점수, 순위, DB 저장은 작동합니다. 코드 채점은 사용할 수 없다고 표시하며 호스트에서 대신 실행하지 않습니다.

제출은 대기열에서 순차 채점합니다. 컨테이너는 네트워크 없음, 읽기 전용 파일시스템, 일반 사용자, 메모리 64MB, CPU 0.5, 프로세스 32개, 10초 제한으로 실행합니다. 내부 JS 컨텍스트에도 실행 제한을 둡니다. 컨테이너에 호스트 폴더나 Docker 소켓을 연결하지 않습니다. 공개 인터넷 서비스로 운영하기 전에는 별도 채점 전용 호스트와 실행 격리 검토가 필요합니다. 이 버전은 학습용 프로토타입입니다.

## 규칙과 저장

- 문제 공개와 제출 마감은 서버 시각으로 판정합니다. 공개 전 문제 내용과 정답은 API에 포함되지 않습니다.
- 문제별 모든 테스트를 통과하면 해결 점수 90점(보안·기능 유지), 시간 보너스 최대 10점을 받습니다. 부분 점수는 없습니다.
- 문제별 최고 점수를 합산하고, 동점은 그 점수에 최종 도달한 시각이 빠른 순으로 정렬합니다.
- 마감 전 접수된 코드는 마감 뒤 채점되어도 접수 시각으로 점수를 계산합니다.
- 공동 복구는 사용자별 문제 해결을 한 번만 계산하며 9회 해결이 목표입니다.
- 다른 브라우저에서도 같은 닉네임·비밀번호로 로그인하면 계정의 기록과 당일 조를 이어갈 수 있습니다.
- SQLite 파일은 `data/game.sqlite`에 저장합니다. 실행 중에는 WAL 보조 파일도 사용합니다. 백업은 서버 종료 후 data 폴더 전체를 복사하세요.
- 개발용 기본 주소는 127.0.0.1입니다. 외부 배포, HTTPS 종료 서버, AI API 연결은 포함되지 않습니다. 외부 AI 도움은 허용합니다.
- 문제 세트는 현재 고정된 샘플입니다. 매일 새 문제가 자동 생성되지는 않습니다. 실제 대회 전에는 비공개 신규 문제와 운영용 문제 관리 기능이 필요합니다.

## 검증

```powershell
node --test tests/*.test.mjs
```

문제 공개 경계, 마감, 한국 시간 일정, 점수, 올바른 패치와 잘못된 패치, 계정 등록·인증·로그아웃·세션 만료·인증 요청 제한, 조의 균형·재접속 유지·지각 참가·날짜별 분리를 검증합니다. API 통합 테스트는 임시 경로의 실제 SQLite 파일에 계정·출석·제출을 저장하고 다른 연결에서 읽어 검증합니다. 고정된 신뢰 가능한 테스트 코드만 로컬 하네스에서 실행하며 실제 사용자 코드는 Docker 전용입니다. Docker 환경에서의 자원 제한 검증은 별도로 수행해야 합니다.

## 온라인 배포 준비

**Vercel + 게임 API/DB + 별도 채점 서버 배포 절차는 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고하세요.** `deploy/`에 Docker Compose·HTTPS·서비스·환경 변수 예제가 있고 `.github/workflows/verify.yml`에서 Docker 채점까지 검증합니다. 외부 계정 연결, 유료 서버 생성, DNS와 운영 환경 변수 설정은 아직 별도 단계입니다.

GitHub는 필수가 아닙니다. 코드를 직접 서버에 올려도 배포할 수 있습니다. GitHub와 연결하면 변경 이력과 자동 배포를 관리하기 편합니다. GitHub Pages 같은 정적 파일 호스팅만으로는 이 Node 서버와 SQLite, Docker 채점기를 실행할 수 없습니다.

배포 서버에서는 `HOST=0.0.0.0`, 서비스가 지정한 `PORT`, `PUBLIC_ORIGIN=https://실제게임주소`, 영구 저장 경로의 `SECURITY_GAME_DB`를 설정하세요. HTTPS는 배포 환경에서 제공해야 합니다. `PUBLIC_ORIGIN`은 요청 출처 검증과 Secure 쿠키 설정에 사용합니다. SQLite는 영구 디스크가 연결된 단일 게임 서버를 전제로 합니다. 여러 서버로 확장할 때는 DB와 세션·요청 제한 구조를 조정해야 합니다.
